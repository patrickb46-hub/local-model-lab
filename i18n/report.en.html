Local Model Lab · Distillation vs Reinforcement Learning

One copy of Qwen3.5-2B split into two isolated branches · Shared task axis: junior-high math problems + a fixed structured-output format · Evaluation set of 52 problems (frozen before training; neither branch had seen them)

1. Bottom Line First

  • Core claim · L2 (problems the teacher fails systematically but base still has a chance at): teacher 0.0%; A1 · Distilled 60 steps 16.7% ↑; B · RL 56.2% ↑; C · SFT→RL (matched budget) 54.2% ↑. Both method families surpass the teacher (this tier is not discriminative enough; read it together with the deltas and significance).
  • Control · L1 (problems the teacher can solve): teacher 71.7%; A1 · Distilled 60 steps 53.3%; B · RL 66.7%; C · SFT→RL (matched budget) 70.0%. This is distillation’s home turf (these are exactly what it learns). If distillation does not lead here, its imitation never really took effect.
  • A1 · Distilled 60 steps: overall accuracy vs base -2.6pt, format-compliance rate +0.6pt — actually worse. Diversity 32%, teacher similarity 61%.
  • B · RL: overall accuracy vs base +18.6pt, format-compliance rate -7.7pt — a gain. Diversity 38%, teacher similarity 46%.
  • C · SFT→RL (matched budget): overall accuracy vs base +20.5pt, format-compliance rate -0.6pt — a gain. Diversity 22%, teacher similarity 54%.
  • A1 vs B (strictly equal steps; the only variable is “imitation vs verifier”): 1 problem only A1 solves, 13 problems only B solves (52 in total) → McNemar p=0.0018, significant.
  • B vs teacher: 14 problems only B solves, 4 problems only the teacher solves (52 in total) → McNemar p=0.0309, significant.
  • Reference: external strong model (DeepSeek V4 Pro · cloud API): 95.5%; the best arm C · SFT→RL (matched budget) 51.3% — a clear gap (44.2pt apart). One honest side observation: the cloud API takes 2.0s per item, this machine 85.6s per item — on a machine with no GPU, local inference is an order of magnitude slower.
How to read this: the distillation branch A looks at “how closely it imitates the teacher”; the RL branch B looks at “whether the reward curve trends upward”. The two process metrics come from different sources by nature; only numbers on the same downstream problem set can be compared side by side.

Tiering is defined solely by base and teacher measurements, entirely independent of the training method — so it does not amount to “picking problems that favor oneself”. The problems used were frozen before training.
L1: the teacher solves it → distillation’s home turf (these are exactly what it learns).
L2: the teacher fails systematically while base may still get it right → RL’s battlefield. Distillation’s data pipeline has filter_correct, which drops every sample the teacher answered wrong, so it has never seen the correct solution to such problems, and can only stay at the base level; RL, by contrast, needs only a verifiable grader, not a “reference solution”.
L3: both fail completely → ceiling evidence, used to show that “not every problem can be solved by method”.

6. Training Process

Whether the loss falls steadily determines whether distillation actually learned anything; whether the reward curve trends upward overall and format compliance rises at the same time determines whether RL actually trained the behavior in. A rising reward alone, with diversity dropping to 0, usually means “learned to fill in a template” rather than “learned to solve problems”.

7. Effect of thinking Mode (On vs Off)

⚠ This table cannot be compared across rows — each role has a different token budget, forced by this machine’s compute, not a difference in model capability.
The local roles (base/A/B) have a budget of 384 tokens (including thinking). In practice, with thinking on, their reasoning consumes the entire budget and the actual answer is truncated before it even begins — so the accuracy shown in the “on” column is 0%.
The Ollama roles (qwen4b / teacher) are likewise capped at 384; only 33%/0% reached the actual answer.
The cloud role (DeepSeek V4 Pro) has a budget of 1024, leaving room after the reasoning is written, hence 100%.
Conclusion: the only valid information in this table is “when the budget is insufficient, thinking mode makes the output worse”, not “who thinks better”. To make a real comparison of thinking ability, one would have to raise think_max_new_tokens to above 1500 — but that means over 15 minutes per problem on this machine, which is not realistic this round.
One interesting side observation: the chain of thought of the original Qwen3.5-2B is in English (output looks like Thinking Process: 1. Analyze the Request…), not Chinese.

Mechanism: local models go through the chat template’s enable_thinking; Ollama models use the API’s think parameter; the cloud API uses the thinking field ({"type":"disabled"} to disable), and the reasoning content is returned as a separate content block, which is more reliable than parsing <think> tags. The reasoning block must be stripped before grading — models also emit format markers inside their reasoning; without stripping, “talking to oneself” would be counted as the actual answer.
Note that the two columns of this table also use different definitions: “off” is the full protocol (all problems, multiple samples), while “on” is a small-sample probe (with thinking on, the output grows several-fold; at 1.32 tok/s on this machine, an unbounded run would not finish).

9. Definitions

format-compliance rate: the three sections 【思路】/【步骤】/【答案】 all present and in the correct order, judged programmatically.
task accuracy: the 【答案】 field is extracted and compared against a program-generated ground truth, with normalization for fractions / decimals / units / equivalent forms.
teacher similarity: text similarity between this model’s output and the 9B teacher’s output (ratio after whitespace normalization).
output diversity: the average difference across repeated samples of the same problem; closer to 0 means more convergent output.
general-capability retention: keyword hit rate on chit-chat / general-knowledge quizzes, used to watch for catastrophic forgetting.
Sampling protocol: each problem is sampled 3 times at temperature 0.7; the ± in the table is the standard deviation of per-problem means. Greedy is not reported because temperature-0 decoding is deterministic — repeated runs give identical results, so averaging does nothing to reduce error.
Diversity reuses these same 3 samples from the main run (pairwise differences within a problem); no separate pass is needed.
thinking mode: both are tested. With thinking on, strip <think>…</think> before grading; the “on” condition, because its output is too long, uses a small-sample probe and therefore serves only as a trend reference.
